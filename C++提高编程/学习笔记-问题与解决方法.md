# C++ 学习笔记

## 一、 C++ 语言特性与模板推导

### 1. 类模板推导规则演变 (C++17)
- **旧规则 (C++14及以前)**：类模板不支持自动类型推导，必须显式指定类型参数。例如 `Box<int> b(10);` 是合法的，而 `Box b(10);` 会导致编译错误。
- **新规则 (C++17)**：引入 CTAD (类模板参数推导)。编写 `Box b(10);` 时，编译器会自动推导 `T` 为 `int`。
- **实践建议**：虽然现代 C++ 支持自动推导，但在涉及复杂类型或为提升代码可读性时，显式指定 `<类型>` 依然是推荐做法。

## 二、 自定义数组类 MyArray 底层剖析

### 1. 核心机制
手动实现 MyArray 是理解 C++ 内存管理的重要实践，其核心机制包括：
- **深拷贝**：在拷贝构造函数中 `new` 新内存并逐个复制数据，避免两个对象指向同一块内存导致重复释放。
- **运算符重载**：
  - `operator=`：处理对象赋值，需实现旧内存释放与深拷贝。
  - `operator[]`：提供类似原生数组的下标访问方式。

### 2. 致命陷阱：自赋值问题
在重载 `operator=` 时，若缺少自赋值判断，执行 `a = a;` 会导致程序崩溃或数据异常。
- **原因分析**：深拷贝的标准执行顺序为“释放旧内存 -> 开辟新内存 -> 拷贝源数据”。自赋值时，`this->pAddress` 与 `arr.pAddress` 指向同一块内存。第一步 `delete[] this->pAddress` 会直接销毁源数据，后续拷贝操作将读取已释放的非法内存。
- **修正方案**：在函数开头加入自赋值判断。
```cpp
MyArray& operator=(const MyArray& arr)
 {
    // 1. 判断是否为自赋值
    if (this == &arr) {
        return *this;
    }
    // 2. 释放原有内存
    // 3. 进行深拷贝
    return *this;
}
```

### 3. 默认构造函数的必要性
若自定义类（如 `Person`）需要放入 `MyArray` 或 STL 容器中，必须提供无参构造函数（默认构造函数）。
- **触发点**：`MyArray` 构造函数中的 `new T[this->m_Capacity]`。
- **底层机制**：`new T[N]` 不仅分配内存，还会自动调用 N 次构造函数来初始化对象。如果 `Person` 只有带参构造函数，编译器不会自动生成无参构造函数，导致 `new Person[12]` 因找不到匹配的无参构造函数而报错。

### 4. 内存模型与预分配机制
以 `MyArray<Person> arr(12);` 为例：
- **动作**：开辟内存空间，并调用 12 次 `Person()`。
- **内存状态**：创建了 12 个由默认构造函数初始化的“占位对象”。
- `arr.Push_Back(p1);` 执行时，将 `p1` 的数据拷贝（覆盖）到数组的第一个占位位置。

### 5. operator[] 的越界保护与 const 修饰
- **差一错误陷阱**：错误写法 `if (index < 0 || index > this->m_Size)`。当数组大小为 5（合法下标 0~4），`index = 5` 时，`5 > 5` 为假，未触发保护。正确写法应为 `index >= this->m_Size`。
- **断言保护**：下标访问应增加断言以暴露越界问题，避免读取脏数据。

```cpp
T& operator[](int index) 
{
assert(index >= 0 && index < this->m_Size);
return this->pAddress[index];
}
```
- **const 成员函数**：不修改成员变量的函数应加 `const` 修饰。需提供 `const` 版本的 `operator[]`，以便 `const` 对象或 `const` 引用调用。

```cpp
const T& operator[](int index) const 
{
return this->pAddress[index];
}
```

### 6. 尾删法（Pop_Back）的逻辑删除本质
`Pop_Back()` 的实现通常仅为 `this->m_Size--`。
- **本质**：未销毁对象，未释放内存，仅将其标记为“不可访问”，属于逻辑删除。
- **隐患**：若 `T` 是管理资源句柄的复杂对象，该对象依然占用资源，直到被下次 `Push_Back` 覆盖或数组析构。此行为与 STL `vector` 标准一致。

## 三、 STL 标准模板库与迭代器

### 1. for_each 与迭代器的关系
STL 的设计哲学为“容器、算法、迭代器”分离。`for_each` 等算法本身不认识容器，完全依赖传入的起始和结束迭代器（如 `v.begin()` 和 `v.end()`），底层实现为基于迭代器的 `while(first != last)` 循环。

### 2. 容器遍历方式对比
- **范围 for 循环 (C++11)**：最简洁，日常最常用。
```cpp
for (auto val : v) { cout << val << endl; }
```
- **for_each + Lambda (C++11)**：逻辑内聚性强。
```cpp
for_each(v.begin(), v.end(), [](int val){ cout << val << endl; });
```
- **传统 for 循环 + 迭代器**：适用于需要直接操作迭代器的场景（如 `erase` 删除元素、跳步遍历）。
- **while 循环 + 迭代器**：不推荐，易造成作用域污染和逻辑错误。

### 3. 解引用与运算符优先级
当容器存放指针（如 `vector<Person*>`）时，迭代器 `it` 相当于二级指针（`Person**`）。
由于 `->` 的优先级高于 `*`，若编写 `*it->m_Name`，编译器会先执行 `it->m_Name`，但指针本身没有 `m_Name` 成员，导致报错。
**正确写法**：`(*it)->m_Name`，通过括号强制先解引用迭代器，取出指针后再访问成员。

### 4. `.` 与 `->` 的使用场景
核心原则：`.` 用于访问对象的成员，`->` 用于访问指针指向的对象的成员。
- **存对象 (`vector<Person>`)**：
  - `it` 相当于 `Person*`，可用 `it->m_Name`。
  - `*it` 相当于 `Person` 对象，可用 `(*it).m_Name`。
- **存指针 (`vector<Person*>`)**：
  - `it` 相当于 `Person**`。
  - `*it` 相当于 `Person*` 指针，必须用 `(*it)->m_Name` 或 `(**it).m_Name`。
